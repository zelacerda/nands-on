# Specification: Importar e Exportar Biblioteca de Chips (JSON)

**Track ID:** import-export_20260629
**Type:** Feature
**Created:** 2026-06-29
**Status:** Draft

## Summary

Tornar funcionais as opções **Import** e **Export** do menu de comandos (≡), hoje
placeholders, permitindo exportar toda a biblioteca de chips para um arquivo `.json`
versionado e reimportá-la depois (substituindo a biblioteca atual).

## Context

O NANDS-ON é uma aplicação 100% client-side que persiste a biblioteca de chips no
IndexedDB. O `tech-stack.md` já prevê **Export/Import em JSON** para backup e
compartilhamento de projetos. Hoje os botões `#cmd-import` e `#cmd-export` existem no
menu, mas seus handlers apenas fecham o menu (placeholders, ver `src/main.ts`). Esta track
implementa a serialização/desserialização da biblioteca de chips (`ChipDefinition[]`).

## User Story

Como usuário do NANDS-ON, quero exportar minha biblioteca de chips para um arquivo JSON e
reimportá-la depois, para fazer backup dos meus circuitos e compartilhá-los com outras
pessoas.

## Acceptance Criteria

- [ ] Clicar em **Export** baixa um arquivo `.json` contendo toda a biblioteca de chips do
      usuário, num envelope versionado: `{ "format": "nands-on", "version": "1.0", "chips": [...] }`.
- [ ] Clicar em **Import** abre um seletor de arquivo (`<input type="file">` oculto); ao
      escolher um JSON válido, os chips são carregados, **substituindo toda a biblioteca
      atual sem perguntar**, persistidos no IndexedDB, e a paleta é atualizada.
- [ ] Importar um arquivo cuja `version` seja diferente de `"1.0"` (ou cujo `format` não
      seja `nands-on`) é **rejeitado** com mensagem de erro clara, sem alterar o estado
      atual.
- [ ] Arquivos inválidos, corrompidos ou com estrutura de chips inconsistente são
      rejeitados com mensagem de erro clara, preservando a biblioteca atual.
- [ ] Os botões deixam de ser placeholders e ficam totalmente funcionais no desktop e no
      mobile (toque).
- [ ] Mensagens de erro/sucesso passam por `strings.ts` (preparadas para i18n).

## Dependencies

Nenhuma dependência externa ou de track incompleta. Reaproveita código existente:
`persistence.ts` (`loadChips`/`saveChips`/`clearChips`), `ChipLibrary`/`captureDefinition`
em `chip.ts`, e a lógica de atualização da paleta em `main.ts`.

## Out of Scope

- Exportar/importar o **espaço de trabalho atual** (circuito em edição) — apenas a
  biblioteca de chips.
- **Mesclar** bibliotecas ou resolução seletiva de conflitos — o import sempre substitui
  tudo.
- **Migração entre versões** de formato — apenas a versão `1.0` é aceita; outras são
  rejeitadas (campo `version` garante incompatibilidade explícita com formatos futuros).
- Compartilhamento via URL ou nuvem — apenas arquivo local `.json`.

## Technical Notes

- Envelope JSON: `{ "format": "nands-on", "version": "1.0", "chips": ChipDefinition[] }`.
- **Export**: serializar via `Blob` + elemento `<a download>`, nome sugerido
  `nands-on-export.json`.
- **Import**: `<input type="file" accept="application/json">` oculto, acionado pelo botão;
  ler com `FileReader`/`text()`, fazer `JSON.parse` protegido, validar `format`/`version` e
  a estrutura dos chips antes de aplicar.
- Após import bem-sucedido: persistir (`clearChips` + `saveChips`), recarregar a
  `ChipLibrary` e atualizar a paleta — idealmente sem exigir reload da página.
- Validação da versão centralizada numa constante (`FORMAT_VERSION = '1.0'`).
