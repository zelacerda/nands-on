# Specification: Reorganização da UI do Editor

**Track ID:** ui-redesign_20260614
**Type:** Feature
**Created:** 2026-06-14
**Status:** Draft

## Summary

Reorganizar o layout da interface do editor de circuitos para uma disposição mais
escalável e amigável a mobile: barra de componentes **vertical** com scroll, caixa
dedicada de I/O, menu de comandos (≡), e uma barra de ações contextual (EDIT / RENAME /
DELETE) para o item selecionado. Sem mudança na lógica de simulação ou interação central.

## Context

NANDS-ON é um simulador de lógica digital 100% no browser (TypeScript + Canvas, vanilla,
sem framework), com foco em simplicidade didática e uso em smartphones/tablets. Hoje a
paleta é horizontal e os comandos (CLEAR DB, ABOUT) e ações (EDIT, DELETE, renomear por
duplo-toque) estão espalhados pelos cantos da tela. Conforme o usuário cria mais chips, a
paleta horizontal não escala e o duplo-toque para renomear é pouco confiável no touch.
Esta reorganização prepara a UI para crescer (mais componentes) e melhora a usabilidade
mobile, mantendo todo o comportamento de simulação intacto.

## User Story

Como usuário do simulador (em desktop ou mobile), quero uma interface organizada — com a
lista de componentes em coluna rolável, comandos agrupados num menu e ações claras para o
item selecionado — para que eu consiga criar e gerenciar circuitos de forma confortável
mesmo conforme a biblioteca de chips cresce.

## Acceptance Criteria

- [ ] Os botões **IN** e **OUT** (circulares) ficam numa **caixa dedicada** no topo-esquerda,
      acima da barra de componentes, mantendo o arrastar-para-criar atual.
- [ ] A **barra de componentes** é **vertical** (coluna) na lateral esquerda, listando NAND
      e os chips criados; o **MAKE** (verde) aparece dentro dela quando há ≥1 IN e ≥1 OUT.
- [ ] A barra de componentes exibe controles de **scroll (▲ / ▽)** apenas quando o conteúdo
      excede a altura disponível; caso contrário ficam ocultos.
- [ ] Existe um **menu de comandos (≡)** no topo-direita que, ao ser acionado, exibe os itens
      **IMPORT**, **EXPORT**, **CLEAR DB** (destaque/laranja) e **ABOUT**.
- [ ] **IMPORT** e **EXPORT** aparecem como itens do menu, mas são **placeholders** (sem
      funcionalidade de serialização nesta track).
- [ ] **CLEAR DB** e **ABOUT** passam a viver dentro do menu ≡ (deixam de ser botões soltos
      nos cantos), preservando seus comportamentos atuais.
- [ ] Uma **barra de ações contextual** (EDIT / RENAME / DELETE) aparece na parte
      **inferior-central** quando um item está selecionado, mostrando **apenas as ações
      aplicáveis** ao contexto:
  - Chip selecionado na barra lateral: EDIT (abre circuito interno), RENAME (renomeia a
    definição), DELETE (remove da biblioteca).
  - Nó de entrada/saída selecionado no canvas: RENAME (rótulo), DELETE.
  - Outros nós/fios selecionados no canvas: DELETE.
- [ ] O **renomear por duplo-toque/duplo-clique é removido**; renomear passa a ser feito
      exclusivamente pela barra de ações contextual (RENAME).
- [ ] O **callout do tutorial ("Step X of N")** é reposicionado para o **topo-central**.
- [ ] Toda a lógica de interação existente (drag-to-create, seleção, criação de fios, make,
      edição de chip, tutorial, persistência) continua funcionando como antes.
- [ ] A interface permanece utilizável em telas de smartphone/tablet (toque) e desktop.

## Dependencies

Depende do código de UI existente (`index.html`, `src/main.ts`, `src/style.css`,
`src/strings.ts`, `src/tutorial.ts`). Sem dependência de tracks incompletos.

## Out of Scope

- Funcionalidade real de **IMPORT/EXPORT** (serialização/deserialização JSON) — apenas
  os botões/placeholders entram aqui; a lógica fica para track futuro.
- **Seleção múltipla** e **delete múltiplo** — track separado.
- **Restrição do pan** (arrastar só com botão do meio/direito do mouse ou dois dedos no
  touch) — track separado.
- Qualquer mudança na lógica de simulação, propagação de sinais ou modelo de dados.

## Technical Notes

- Stack: TypeScript strict, Canvas 2D, vanilla (sem framework). UI em `index.html` +
  `src/style.css`; orquestração em `src/main.ts`; textos em `src/strings.ts` (i18n-ready
  via `data-i18n`).
- Reaproveitar o sistema atual de drag-to-create (`attachPaletteDrag`), seleção
  (`selection`), `canMake()`, edição de chip (`#edit-bar`) e tutorial.
- Novos textos (IMPORT, EXPORT, COMMANDS, EDIT, RENAME, DELETE) devem ser adicionados em
  `src/strings.ts` com `data-i18n`, mantendo a base de i18n.
- A barra de componentes vertical precisa de uma estratégia de scroll própria (▲/▽) que só
  apareça em overflow — pode ser CSS overflow + botões condicionais.
- Validar via `npm run build` antes de finalizar (vitest não pega erros de tipo).
