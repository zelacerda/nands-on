# Specification: Tradução da Interface para Inglês (com base p/ i18n)

**Track ID:** translate-ui_20260604
**Type:** Chore
**Created:** 2026-06-04
**Status:** Draft

## Summary

Traduzir todos os textos da interface visíveis ao usuário de português para inglês,
centralizando-os em um módulo único de strings (fonte única de verdade) que deixa o
terreno preparado para internacionalização (i18n) futura — sem instalar bibliotecas.

## Context

O **From NAND to CPU** é um simulador de lógica digital 100% no browser, voltado a
estudantes e entusiastas. O objetivo deste track é abrir a aplicação para um **público
internacional**, adotando o inglês na UI desde já. A referência do projeto
(Digital-Logic-Sim) também é em inglês. Código, comentários, nomes de variáveis e
mensagens de log/erro internas (dev-facing) **permanecem em português**, conforme a
linguagem já adotada no repositório.

## Problem Description (motivação)

Hoje os textos da UI estão hardcoded em português, espalhados entre o `index.html`
(estáticos) e arquivos `src/*.ts` (dinâmicos). Isso (a) bloqueia o alcance a um público
internacional e (b) torna qualquer i18n futura custosa. Centralizar e traduzir agora
resolve o alcance imediato e cria a base para múltiplos idiomas depois.

## Acceptance Criteria

- [ ] Existe um módulo central de strings (ex.: `src/strings.ts`) com todas as strings de
      UI definidas por chave, em inglês.
- [ ] Os textos estáticos do `index.html` são preenchidos em runtime a partir do módulo
      central (ex.: via atributos `data-i18n` + bootstrap em JS), e não mais hardcoded.
- [ ] Os textos dinâmicos do TS referenciam o módulo central (nenhuma string de UI em PT
      remanescente em `main.ts` / `chip.ts`).
- [ ] Traduções aplicadas conforme acordado: `Entrada → IN`, `Saída → OUT`,
      `Limpar banco → Clear DB`, `Salvar edição → Save`, `Cancelar → Cancel`,
      `Criar → Create`, `Editar → Edit`, `Excluir → Delete`, `Fazer → Make`,
      `Editando: X → Editing: X`, etc. (IN/OUT em caixa alta).
- [ ] `index.html` com `lang="en"`.
- [ ] App roda sem regressões visuais/funcionais; testes existentes passando.

## Out of Scope

- **Mensagens dev-facing permanecem em PT**: `throw new Error(...)` (ex.: `main.ts`

- **`connection.ts` reasons**: as mensagens de `validateConnection` (L24/L29/L36)
  **não** são exibidas na UI (apenas `.ok` é consumido em `main.ts`), portanto ficam
  fora do escopo de tradução.
- Código, comentários e nomes de identificadores — permanecem em português.
- Instalação de biblioteca de i18n e suporte real a múltiplos idiomas (apenas a base
  estrutural; só `en` preenchido).
- Tradução de `conductor/`, README ou documentação.

## Technical Notes

- Abordagem aprovada: **centralizar tudo em módulo de strings**; HTML estático passa a
  ser preenchido por JS (ex.: `data-i18n="palette.input"` + função de bootstrap que varre
  o DOM no carregamento). Sem lib de i18n.
- Estrutura do módulo pensada para evoluir a i18n (chaves agrupadas por contexto). Suporte
  a placeholders simples para textos interpolados (ex.: `Editing: {name}`).
- TypeScript em modo strict — chaves tipadas para evitar referência a chave inexistente.
