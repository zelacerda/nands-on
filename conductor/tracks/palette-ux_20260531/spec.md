# Specification: UX da Paleta — Reordenação, Cor de I/O e Arrastar-para-Criar

**Track ID:** palette-ux_20260531
**Type:** Feature
**Created:** 2026-05-31
**Status:** Draft

## Summary

Refinar a UX da paleta de componentes: reordenar as primitivas (Entrada, Saída, NAND),
diferenciar visualmente os pinos de I/O dos componentes lógicos via cor, e substituir o
clique-no-centro por arrastar-e-soltar para criar instâncias no ponto onde o ponteiro é
solto.

## Context

O **From NAND to CPU** é um simulador de lógica digital 100% no browser, com editor em
`<canvas>` e paleta de componentes em HTML (`#palette`). Hoje a paleta lista as primitivas
na ordem `NAND`, `Entrada`, `Saída`, seguidas pelos chips criados. Clicar em qualquer botão
adiciona uma instância no centro da viewport (`addNodeAtCenter` / `addChipInstanceAtCenter`).
Visualmente, todas as primitivas (`nand`, `input`, `output`) compartilham a cor de corpo
`body` (`#2d333b`), enquanto os chips criados usam `chipBody` (`#363c4a`).

Como a aplicação tem foco didático e deve funcionar bem em desktop e mobile (toque), a
interação de criação e a leitura visual dos componentes são pontos centrais da experiência.

## User Story

Como usuário do simulador, quero arrastar componentes da paleta para o ponto exato do
editor e distinguir visualmente entradas/saídas dos componentes lógicos, para montar
circuitos de forma mais intuitiva e ler o circuito com menos esforço.

## Acceptance Criteria

- [x] A paleta exibe as primitivas na ordem **Entrada, Saída, NAND**; os botões de chips
      criados continuam após as primitivas.
- [x] O NAND é renderizado no canvas com a **mesma cor dos chips criados** (cor de
      componente lógico), enquanto **Entrada e Saída** usam uma cor distinta de I/O.
- [x] Arrastar (mouse ou toque) a partir de qualquer botão da paleta — primitivas **e**
      chips criados — e soltar sobre o editor cria uma nova instância **centrada no ponto
      onde o ponteiro foi solto** (em coordenadas de mundo).
- [x] Soltar o arrasto **fora** da área do editor não cria nenhuma instância.
- [x] Um **clique simples** (sem arrasto) em um botão da paleta **não cria** instância e
      não tem efeito visível (reservado para o futuro fluxo de edição).
- [x] A interação funciona em **desktop (mouse)** e em **dispositivos de toque**.

## Dependencies

Depende do código existente da paleta e do editor:
- `index.html` — ordem dos botões `data-add` em `#palette`.
- `src/main.ts` — handlers da paleta, `addNodeAtCenter`, `addChipInstanceAtCenter`,
  `refreshPalette`, conversão `screenToWorld` da câmera.
- `src/render.ts` — paleta de cores (`COLOR.body` / `COLOR.chipBody`) e `drawNode`.
- `src/model.ts` — `PrimitiveType`, `NODE_SIZE`, `chipSize`.

Não depende de tracks incompletos (os tracks `visual-editor` e `reusable-chips` estão
concluídos).

## Out of Scope

- Fluxo de **edição** de componentes (futuro botão "Editar") — apenas se reserva o clique
  simples para ele, sem implementá-lo agora.
- Pré-visualização ("ghost") do componente seguindo o ponteiro durante o arrasto, salvo se
  trivial; não é requisito.
- Mudanças nas dimensões, pinos ou comportamento de simulação dos componentes.
- Persistência, export/import, ou qualquer alteração de armazenamento.

## Technical Notes

- A cor passa a ser função da **categoria** do nó (I/O vs. lógico), não do tipo bruto.
  Sugestão: tratar `input`/`output` como I/O e `nand`/`chip` como lógicos em `drawNode`.
- O arrasto começa em elementos HTML (`<button>`) e termina sobre o `<canvas>`. Como o
  resto do editor usa Pointer Events, recomenda-se usar `pointerdown` no botão +
  `setPointerCapture` para rastrear o movimento até o `pointerup`, evitando a API nativa
  de HTML5 drag-and-drop (que tem suporte irregular em toque).
- Diferenciar **clique** de **arrasto** por limiar de deslocamento (ex.: alguns px) para
  não disparar criação em toques curtos.
- A posição de drop deve ser convertida de coordenadas de tela do canvas para mundo
  (`camera.screenToWorld`) e a instância centrada nesse ponto (descontando `w/2`, `h/2`),
  reaproveitando a lógica já presente em `addNodeAtCenter`/`addChipInstanceAtCenter`.
