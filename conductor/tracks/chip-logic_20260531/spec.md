# Specification: Lógica de Simulação dos Chips

**Track ID:** chip-logic_20260531
**Type:** Feature
**Created:** 2026-05-31
**Status:** Draft

## Summary

Implementar o motor de simulação lógica dos circuitos: entradas booleanas que
alternam de estado ao serem clicadas (quando já selecionadas) e saídas booleanas
que acendem conforme a propagação da lógica do circuito, tendo a porta NAND como
única primitiva lógica.

## Context

O **From NAND to CPU** é um simulador de lógica digital 100% no browser, cujo
objetivo didático é mostrar como uma CPU é construída a partir da porta NAND. Os
tracks anteriores entregaram toda a camada **estática**: modelo de dados
(`model.ts`), armazenamento (`store.ts`), renderização em Canvas (`render.ts`),
interação por mouse/toque (`main.ts`) e chips reutilizáveis com composição
hierárquica (`chip.ts`). Hoje, no entanto, **não existe nenhuma lógica de
simulação** — não há estado booleano nos nós, não há propagação de sinal e nada
acende. Este track entrega o "cérebro" que faltava para validar visualmente que
um circuito montado funciona.

## User Story

Como estudante, quero clicar nas entradas do meu circuito e ver as saídas
acenderem conforme a lógica, para validar visualmente que o circuito que montei
funciona corretamente.

## Acceptance Criteria

- [ ] Clicar num componente de entrada **não selecionado** apenas o seleciona
      (comportamento atual preservado); clicar nele quando **já selecionado**
      alterna seu estado booleano (ligado/desligado), com indicação visual de
      "aceso".
- [ ] O motor de simulação propaga os sinais pelas conexões e pela porta NAND do
      circuito, avaliando de forma combinacional até estabilizar.
- [ ] Componentes de saída refletem (acendem/apagam) o resultado da lógica do
      circuito em tempo real.
- [ ] Os fios/conectores indicam visualmente se carregam sinal ligado ou
      desligado.
- [ ] Chips reutilizáveis são avaliados recursivamente a partir de sua topologia
      interna (`ChipDefinition.internal`), produzindo as saídas corretas para as
      entradas dadas.

## Dependencies

Depende de código existente (tracks já concluídos):

- Modelo de dados e geometria: `src/model.ts` (`CircuitNode`, `Pin`, `Wire`,
  `ChipDefinition`, `createPins`).
- Armazenamento em memória: `src/store.ts` (`CircuitStore`).
- Renderização no Canvas: `src/render.ts` (`drawNode`, `drawWires`).
- Máquina de estados de interação (pointer handlers): `src/main.ts`.
- Chips reutilizáveis e captura/biblioteca: `src/chip.ts`.

## Out of Scope

- Outras portas lógicas além da NAND (AND, OR, NOT etc. — o usuário as monta a
  partir da NAND).
- Simulação com atraso/temporização (delay propagation); a avaliação é
  combinacional e instantânea.
- Circuitos sequenciais com realimentação/estado (flip-flops, ciclos de
  feedback).
- Persistência do estado dos sinais no IndexedDB.

## Technical Notes

- Criar um módulo `src/simulator.ts` responsável por avaliar o circuito de forma
  **combinacional**: dado o conjunto de valores das entradas, propaga os sinais
  por avaliação iterativa (relaxation) até o estado estabilizar, evitando loop
  infinito com um limite máximo de iterações.
- A **NAND** é a única primitiva lógica (`out = !(in0 && in1)`). Pinos `input`
  fornecem seus valores booleanos; pinos `output` recebem o valor que chega pelo
  fio conectado.
- **Chips** são avaliados recursivamente expandindo sua topologia interna
  (`ChipDefinition.internal`), mapeando os pinos externos do chip para as
  entradas/saídas internas.
- O resultado da simulação é um estado de sinal (ex.: `Map<wireId, boolean>` e
  `Map<nodeId/pinId, boolean>`) consumido por `render.ts` para colorir fios,
  pinos e acender outputs/inputs.
- A simulação roda integrada ao loop de render de `main.ts`, recalculando quando
  o circuito ou os valores de entrada mudam.
- Toggle do input: detectar no `pointerdown`/`pointerup` de `main.ts` o clique
  sobre um nó `input` que já está selecionado e alternar seu `value`.
